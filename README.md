# Лабораторная работа №8

## Описание проекта

Программа для работы с коллекцией маршрутов. Сервер хранит маршруты и пользователей в PostgreSQL, а подключаться к нему можно из консольного клиента или графического приложения. Для работы с коллекцией нужны регистрация или вход в аккаунт.

В проекте реализованы сетевое взаимодействие по TCP, работа сервера с несколькими клиентами, сохранение данных в базе, асинхронная генерация маршрутов и уведомления для подписчиков. Консольный клиент поддерживает команды и скрипты, а графический клиент показывает маршруты в таблице и на схеме.

## Возможности

- Добавление, изменение и удаление маршрутов.
- Просмотр, сортировка и фильтрация коллекции.
- Регистрация и вход пользователей. Удалять и изменять можно только свои маршруты.
- Хранение пользователей и маршрутов в PostgreSQL.
- Запуск генерации маршрутов в фоновой задаче и просмотр её статуса.
- Подписка на уведомления об изменениях коллекции.
- Выполнение команд из файла в консольном клиенте.
- Графический интерфейс с таблицей, фильтрами, просмотром деталей и визуализацией маршрутов.
- Переключение языка графического интерфейса: русский, английский, словенский и итальянский.

## Команды консольного клиента

Элементы маршрута для команд `add`, `add_if_max` и `update` вводятся интерактивно. Идентификатор и дата создания назначаются сервером.

| Команда | Описание |
|---|---|
| `add` | Добавить маршрут |
| `add_if_max` | Добавить маршрут, если он больше максимального элемента коллекции |
| `average_of_distance` | Вывести среднее значение поля `distance` |
| `clear` | Удалить свои маршруты |
| `execute_script <имя_файла>` | Выполнить команды из файла |
| `exit` | Завершить работу клиента |
| `filter_less_than_distance <distance>` | Вывести маршруты с расстоянием меньше заданного |
| `help` | Показать справку по командам |
| `history` | Показать последние 14 введённых команд |
| `info` | Показать информацию о коллекции |
| `logout` | Выйти из аккаунта |
| `remove_all_by_distance <distance>` | Удалить свои маршруты с заданным расстоянием |
| `remove_by_id <id>` | Удалить свой маршрут по идентификатору |
| `remove_first` | Удалить первый свой маршрут в коллекции |
| `show` | Показать маршруты |
| `update <id>` | Изменить свой маршрут по идентификатору |
| `status` | Показать информацию о текущем аккаунте |
| `generate_data <count>` | Запустить фоновую генерацию маршрутов |
| `task_status <task_id>` | Проверить состояние задачи генерации |
| `login <login> <password>` | Войти в аккаунт |
| `register <login> <password>` | Создать аккаунт |
| `see <page> <page_size>` | Показать страницу коллекции |
| `subscribe <true/false>` | Включить или выключить уведомления |

При запуске консольный клиент также предлагает войти, зарегистрироваться или выйти. Поэтому для начала работы можно выбрать нужный пункт меню, не вводя `login` или `register` вручную.

## Технологии

- **Java 17** и **Gradle**
- **PostgreSQL** и JDBC для хранения данных
- **TCP SocketChannel** для обмена данными между клиентом и сервером
- **NIO Selector** для ожидания подключений и чтения на сервере
- **ExecutorService** для параллельной обработки сетевых операций и задач
- **JavaFX** и FXML для графического интерфейса
- **JLine** для консольного ввода
- **SHA-256**, соль и перец для хэширования паролей
- Сериализация и сжатие пакетов при передаче
- **Log4j2** для журналирования

## Требования

- JDK 17 или новее
- PostgreSQL 15 или новее
- Gradle Wrapper из репозитория (`./gradlew`)

## Сборка

В корне проекта выполните:

```bash
./gradlew clean buildAll
```

Будут собраны три исполняемых файла в `build/libs/`:

- `server-1.0.jar` — сервер
- `client-1.0.jar` — консольный клиент
- `client-gui-1.0.jar` — графический клиент

Если в системе нет JavaFX runtime для вашей платформы, запускайте графическую версию через Gradle командой `./gradlew runGui`.

## Настройка базы данных

Запустите PostgreSQL. Например, в Linux:

```bash
sudo systemctl start postgresql
```

Сервер читает настройки из `db.properties` в текущей рабочей папке. Создайте этот файл рядом с местом, из которого будете запускать сервер:

```properties
db.host=ХОСТ
db.port=ПОРТ
db.name=НАЗВАНИЕ
db.user=ПОЛЬЗОВАТЕЛЬ
db.password=ПАРОЛЬ
```

Пользователю PostgreSQL нужны права на подключение к серверу и создание базы данных, если `route` ещё не существует. При первом запуске сервер создаёт базу (если это разрешено) и таблицы `users` и `routes`.

Если `db.properties` отсутствует, программа использует значения по умолчанию: `localhost:5432`, база `route`, пользователь `postgres`, пароль `1234567890`.

Для хэширования паролей также можно задать секретный перец. В текущей реализации отдельный файл `peper.properties` не читается, поэтому создавать его не требуется.

## Запуск

Сначала запустите сервер из корня проекта или укажите порт (по умолчанию `8080`):

```bash
java -jar build/libs/server-1.0.jar
java -jar build/libs/server-1.0.jar 8080
```

Сервер принимает команду `exit` в консоли для завершения работы.

Затем в другом терминале запустите один из клиентов на том же компьютере и порту:

```bash
java -jar build/libs/client-1.0.jar 8080
```

Графический клиент:

```bash
java -jar build/libs/client-gui-1.0.jar
```

При запуске без порта консольный клиент подключается к `localhost:8080`. В GUI адрес сервера задаётся в коде, сейчас используется `localhost:8080`.

Также клиенты можно запустить без сборки JAR:

```bash
./gradlew runGui
```

## Скрипты команд

Создайте текстовый файл с командами, по одной на строку, затем вызовите его из консольного клиента:

```text
info
show
average_of_distance
```

```text
execute_script commands.txt
```

Путь к файлу задаётся относительно рабочей папки процесса клиента. Команды, которым нужны значения маршрута, запрашивают их интерактивно.

